## Input and failure guards

`private_player_creation_trial.prepare_from_files` reads one strict original
private record against an expected SHA of the exact bounded bytes parsed. Each
HTTPS child and Carrier verifies that same digest before listeners start and
retains its immutable record. The private current typeIndex must match exact
SHAf1e2385f,7052entries,nil0 and selected creation10/identity3935 UUIDs. File
integrity does not establish native runtime table installation.

The helper fixes only the explicitly proposed slot/keys/indexes/asset/mode;
prepared bytes must equal canonical composition for the supplied fresh record.
The final send boundary verifies typed extent/header/digest. Candidate attempts
are latched before send, remain terminal after failure/exception, and enter no
duplicate-response cache. Earlier heartbeat or required predecessor failure blocks
the candidate. Creation precedes the recurring heartbeat within its tick: a
heartbeat failure later that tick cannot undo the already attempted candidate.
Lifetime admission is not released when its peer closes. When the
option is absent, the existing path remains unchanged.

Explicit user-stop mode changes cumulative packet budgets to rolling one-second
admission limits and keeps the existing heartbeat cadence with at most eight
pending pings. Replay state retains the finite16-bit sequence namespace and
digests of complete validated record streams; exact duplicates resend cached
bytes. No replay eviction or rollover semantics are guessed. Conflicting sequence
contents, a new lower sequence, cursor exhaustion or uncertain sends terminate
with an explicit protocol failure. This removes policy deadlines; it does not
establish native support for unlimited protocol traffic.

Carrier CLI requires the explicit `--player-creation-candidate`, character path
and SHA, private typeIndex path, `--delivery-mode resource-index`, one occupancy
choice and every current actor/world prerequisite. Ancillary inputs without the
flag fail. Queue's supplied-record CLI requires its character path/SHA/occupancy
together. Paths, hashes and original schema are checked before certificate/log/
listener startup. Logs contain allowlisted lengths, counters, digests and rejection
categories; no character/name/ref bytes, request contents or model dumps.

Controller manifest adds an explicit default-off `player_creation_candidate`
boolean and `trial_character_path`, `trial_character_sha256`, `type_index_path`,
`delivery_mode`, plus exactly one occupancy choice. Require all current
actor/world/observer selections and exact unique file bindings before the existing
first system mutation. Both HTTPS processes and Carrier receive the same selected
file, expected SHA and occupancy. The installed client/launcher/EAC remain intact.
The selected preparation adds explicit `user_stop_lifetime: true` and passes
`--until-stopped <run>/stop.request` through the client and services. Each retains
